FUNDAMENTALS

What an MVP Is

Minimum Viable Product: the smallest version of your product that delivers real value to a real user.

An MVP isn't an incomplete product. It's a complete product for a very specific problem. The difference is huge.

THE REAL RISK

The Most Common Mistake

Building too much.

The biggest risk when you have such a powerful tool is falling into feature creep. AI can build anything you ask for. You have to decide what NOT to ask for.

An MVP is defined more by what it excludes than by what it includes.

CHAPTER 01

Defining the Product

From a vague idea to a concrete requirement AI can execute.

SCOPE

How to Define Scope

For every potential feature, ask yourself one question.

For example, for a team task manager MVP:

IN THE MVP
  • Create task
  • Mark as complete
  • View list
BACKLOG
  • Notifications
  • Priorities
  • Categories / Filters
  • Calendar integration

You can build the whole backlog later. With AI, every feature is a matter of hours, not weeks.

IDEA CLARITY

Three Questions to Clarify Your Idea

  1. 01

    What specific problem does it solve?

    Not: I want a social network. Yes: I want an app so my 5-person team can see who's working on what without having to ask.

  2. 02

    For whom, exactly?

    The more specific, the better. Specificity is an advantage, not a limitation.

  3. 03

    What's the minimum moment of value?

    The first instant the user experiences the benefit. Everything else can wait.

REQUIREMENTS

Requirements in Natural Language

Requirements are the translation of an idea into concrete instructions AI can execute.

FORMAT

As a [user type],
I want [feature],
so that [benefit].

EXAMPLE 01

As a team member, I want to create a new task with a name and an assignee, so that everyone knows who's doing what.

EXAMPLE 02

As a manager, I want to see all active tasks and their status on a dashboard, so that I don't have to ask what everyone is working on.

User stories are the language that connects your vision to the AI's instructions.

CHAPTER 02

The Iterative Cycle

The unit of work with generative AI: from requirement to commit in 15–45 minutes.

THE PROCESS

Five Steps That Repeat

  • 01

    Define the requirement

    Write the user story in natural language before opening Claude Code.

  • 02

    Add context to the prompt

    Apply the 5-part structure learned in Module 04: role, context, constraints, format, task.

  • 03

    Review the plan

    Ask the AI to explain what it's going to do before running it. Never run it blindly.

  • 04

    Execute and inspect

    Test it manually as a real user would. Don't trust it without verifying.

  • 05

    Commit or iterate

    If it works: git commit. If not: describe the problem precisely and repeat from step 01.

CYCLE DIAGRAM

The Loop in Practice

This cycle can be completed in 15–45 minutes per feature.

A productive day means 6–10 complete cycles.

CHAPTER 03

Validating Without Knowing Code

How to know whether what the AI built is correct, secure, and solid.

VALIDATION

Five Validation Strategies

  • 01

    Functional test

    Does it do exactly what you asked for? Test it as a real user would, no shortcuts.

  • 02

    Ask the AI

    Explain in simple terms what this code does and what could go wrong.

  • 03

    Check constraints

    Did it follow every constraint you set? Did it change something it shouldn't have?

  • 04

    Regression

    Does everything that worked before still work after the latest change?

  • 05

    Debt review

    If a professional developer saw this code, what would they criticize? Ask the AI.

ARCHITECTURE

The Minimal Architecture

You don't need to know how to implement every layer. You need to know how to describe it to the AI.

TESTING

Testing Without Coding

Tests are your product's life insurance. AI writes them for you, but you need to understand what they cover.

UNIT TESTS

Write tests for the function that calculates the cart total.

INTEGRATION TESTS

Write tests that verify sign-up works end to end.

GUIDED MANUAL TESTS

Give me a list of cases I should test manually to validate login.

KEY HABIT

In the prompt for every new feature, always include: and write the corresponding tests.

ERROR MANAGEMENT

When Something Doesn't Work

WHEN THE AI GETS STUCK

What You Should Do

  • Copy the full error and paste it in: "Here's the error I'm seeing: [error]. What's happening and how do I fix it?"
  • Ask for options: "Give me 3 different ways to solve this problem."
  • Simplify: "Let's do this in smaller steps. First just [part A]."
  • Search for the exact error online (StackOverflow, GitHub Issues).
WHEN TO ASK FOR HUMAN HELP

The Real Limits

  • You've been stuck on the same error for over an hour.
  • The AI proposes solutions that contradict the project's CLAUDE.md.
  • The problem seems to be infrastructure- or platform-related, not your code.
